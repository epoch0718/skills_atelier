# TimeTreeを取り込む

## 対象

- スプレッドシートは atelier顧客データベースで、IDは `14XTckRGgkSI8TQay-eemw25183iHGz-LaNmC9fyVF7g` だよ。
- 取り込み先のシートは `TimeTree` だよ。
- TimeTreeからの取り込みは、ウェブアプリの `scrape01` などでやるよ。

## 決まった手順

- ひとさんが「取り込んで」と言ったら、直近1カ月分を取り込むよ。`scrape01` を呼ぶよ。
- 取り込みはすぐには終わらないよ。起動を受け付けたら、終わるまで待って、終わったことを確認してから伝えるよ。
- 取り込めたら、何件入ったかと期間を伝えるよ。

## 普段は scrape01 だけでいい

- `scrape01` は直近1カ月分だよ。普段の取り込みはこれだけでいいよ。
- `scrape02` は直近2カ月分、`scrape03` は直近3カ月分、`scrape04all` は2025-08から今月までの全部だよ。
- `scrape04all` は、最初だけ・データを直し直すときだけ使うよ。時間が一番かかるよ。
- 毎日16:00には自動で取り込みが動くよ。手動で取り込むのは、すぐ反映してほしいときだけだよ。

## ウェブアプリで取り込む方法（2026-11-23に scrape01 で確認）

- ベースURLは `https://script.google.com/macros/s/AKfycbw0xvM-620l1MwSccqYieFewNR-K20etKAIj1K-Cp6Hg5UQnrvpj2r4PmIi0fl3Jw9A/exec` だよ。
- GETで呼ぶよ。`{URL}?action=scrape01` の形だよ。
- POST（curl -L）では、再デプロイ後に411エラーになることがあるよ。GETで呼ぶのが確実だよ。
- 返答は「起動を受け付けた」という意味で、完了待ちじゃないよ。成功すると `{"ok":true,"action":"scrape01","result":{"ok":true,"http":204,"runId":"...","runUrl":"...","logRow":41}}` が返るよ。
- `runUrl` で進み具合を見られるよ。`LOG_Actions` シートでも確認できるよ。
- 社長には action や URL を書かせないよ。「取り込んで」と言われたら `scrape01` を呼ぶよ。

## 終わったかの確認

- `{"action":"updatePendingActionLogs"}` を呼んで、`LOG_Actions` シートを更新するよ。
- `LOG_Actions` シートで、実行した行の状態が `completed` と `success` になっているか見るよ。
- `scrape01` は起動から完了まで約7分かかったよ（2026-11-23に確認）。
- 完了したら、`TimeTree` シートのH1（最終行の目安）と、最初と最後の行の日付を読んで、何件・いつの期間かを確認するよ。

## 取り込みでは戻らないもの

- 取り込みはTimeTreeカレンダーの予定だけを入れるよ。
- シート側で入れた請求額・請求書No・TODOなどの内容は、取り込みでは戻らないよ。
- TimeTreeシートのデータを消してから取り込むと、予定は戻るけど請求書の内容は空のままだよ。2026-11-23に確認したよ。
- だから、請求書の内容が消えたときは、カルテ編集で入れ直す必要があるよ。

## 検証済みの例

- 2026-11-23に `scrape01` をAPIから呼んだよ。実行IDは 45121760459 で、completed / success になったよ。
- TimeTreeシートには20件入ったよ。2026/11/02（堀内先生）から2026/12/05（万華鏡教室 ハルカス）までで、H1は23だったよ。
- `scrape02` / `scrape03` / `scrape04all` は、タロが手動のメニューから実行して問題なかったよ。APIからはまだ試していないけど、仕組みは `scrape01` と同じだよ。
